# Docker Compose

The main application stack is defined in [docker-compose.yml](../docker-compose.yml). It starts the MQTT broker, sensor simulator, Node-RED, InfluxDB, dashboard importer, and Portainer on one shared Docker network.

Start the full stack:

```bash
docker compose up -d
```

Show logs:

```bash
docker compose logs -f
```

Stop the stack:

```bash
docker compose down
```

---

### Services

| Service | Container | Purpose |
| --- | --- | --- |
| `mosquitto` | `mqtt-broker` | MQTT broker for sensor messages. |
| `sensors` | `sensors-simulator` | Publishes simulated sensor data to MQTT. |
| `nodered` | `node-red` | Processes MQTT messages and writes them to InfluxDB. |
| `node-red-package-installer` | `node-red-package-installer` | One-shot setup service for Node-RED dependencies and credentials. |
| `influxdb` | `influxdb` | Time-series database for sensor data. |
| `influxdb-template-importer` | `influxdb-template-importer` | One-shot setup service that imports InfluxDB dashboards. |
| `portainer` | `portainer` | Web UI for managing Docker. |

---

### Startup Order

Docker Compose starts services based on their `depends_on` rules.

`mosquitto` starts before:
- `sensors`
- `nodered`

`influxdb` must become healthy before:
- `nodered`
- `influxdb-template-importer`

`node-red-package-installer` must finish successfully before:
- `nodered`

The one-shot setup services are expected to exit after they finish:
- `node-red-package-installer`
- `influxdb-template-importer`

This is normal. They are not long-running application containers.

### Ports

| Host port | Container port | Service | Use |
| --- | --- | --- | --- |
| `1880` | `1880` | `nodered` | Node-RED web UI |
| `1883` | `1883` | `mosquitto` | MQTT |
| `9001` | `9001` | `mosquitto` | MQTT over WebSockets |
| `8086` | `8086` | `influxdb` | InfluxDB web UI and API |
| `9443` | `9443` | `portainer` | Portainer web UI |

When opening a web UI on the same machine that runs Docker, use `localhost`.

Examples:

```text
http://localhost:1880
http://localhost:8086
https://localhost:9443
```

When Docker runs on a Debian VM, replace `localhost` with the VM IP address.

Do not use Docker-internal `172.x.x.x` container addresses from the host browser.

### Environment

The stack reads InfluxDB settings from [.env](../.env):

```text
INFLUXDB_ADMIN_USERNAME
INFLUXDB_ADMIN_PASSWORD
INFLUXDB_ORG
INFLUXDB_BUCKET
INFLUXDB_ADMIN_TOKEN
INFLUXDB_URL
```

For Docker Compose, `INFLUXDB_URL` must point to the service name:

```text
INFLUXDB_URL=http://influxdb:8086
```

Inside Docker, containers reach each other by service name, not by `localhost`.

### Persistent Data

The stack stores runtime data in local folders and one named Docker volume.

| Host path / volume | Container path | Used by |
| --- | --- | --- |
| `./mqtt-broker/config` | `/mosquitto/config` | Mosquitto config |
| `./mqtt-broker/data` | `/mosquitto/data` | Mosquitto runtime data |
| `./mqtt-broker/log` | `/mosquitto/log` | Mosquitto logs |
| `./node-red-data` | `/data` | Node-RED flows, settings, credentials, packages |
| `./influxdb/data` | `/var/lib/influxdb2` | InfluxDB database |
| `./influxdb/config` | `/etc/influxdb2` | InfluxDB config |
| `portainer_data` | `/data` | Portainer data |

Most runtime data is ignored by git. The important Node-RED files that are kept in git are:

- [node-red-data/flows.json](../node-red-data/flows.json)
- [node-red-data/settings.js](../node-red-data/settings.js)
- [node-red-data/package.json](../node-red-data/package.json)
- [node-red-data/package-lock.json](../node-red-data/package-lock.json)

The local `node-red-data/flows_cred.json` file is generated by `node-red-package-installer` and is not committed.

### Node-RED Package Installer

The `node-red-package-installer` service exists because the stack uses the official Node-RED image directly instead of building a custom image.

It runs this setup work against the mounted `/data` folder:

```bash
npm ci --omit=dev --prefix /data
mkdir -p /data/lib
generate /data/flows_cred.json from INFLUXDB_ADMIN_TOKEN
chown -R 1000:1000 /data
```

This installs `node-red-contrib-influxdb`, creates the Node-RED library folder, writes the InfluxDB token credentials for the flow, and fixes Linux file ownership for the Node-RED container.

Recreate it after changing Node-RED dependencies or the InfluxDB token:

```bash
docker compose up -d --force-recreate node-red-package-installer nodered
```

---

### InfluxDB Template Importer

The `influxdb-template-importer` service applies dashboard templates from [influxdb/templates](../influxdb/templates).

It runs [influxdb/scripts/apply-templates.sh](../influxdb/scripts/apply-templates.sh), waits until InfluxDB responds, then retries the template import until InfluxDB accepts it.

Re-run the importer after changing templates:

```bash
docker compose up --force-recreate influxdb-template-importer
```

### Common Commands

Start or update the stack:

```bash
docker compose up -d
```

Recreate Node-RED setup:

```bash
docker compose up -d --force-recreate node-red-package-installer nodered
```

Re-run InfluxDB dashboard imports:

```bash
docker compose up --force-recreate influxdb-template-importer
```

View Node-RED logs:

```bash
docker compose logs -f nodered
```

View InfluxDB logs:

```bash
docker compose logs -f influxdb
```

Check resolved Compose configuration:

```bash
docker compose config
```

### Troubleshooting

If Node-RED cannot create `/data/lib`, recreate the Node-RED setup service:

```bash
docker compose up -d --force-recreate node-red-package-installer nodered
```

If Node-RED logs `HttpError: unauthorized access`, the InfluxDB token in Node-RED and the token inside InfluxDB do not match. First recreate the Node-RED setup service:

```bash
docker compose up -d --force-recreate node-red-package-installer nodered
```

If the error continues on a test machine where the existing InfluxDB data is not important, reset InfluxDB:

```bash
docker compose down
sudo rm -rf influxdb/data influxdb/config
docker compose up -d
```

If a browser cannot connect to a `172.x.x.x` address, use the published host port instead:

```text
http://localhost:1880
```

When Docker runs on a VM, use:

```text
http://<vm-ip>:1880
```
